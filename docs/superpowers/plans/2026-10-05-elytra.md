# Elytra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Minecraft's elytra glide, leave a planet, cross the void and land on another planet of the stage, in every movement mode.

**Architecture:** Vanilla `fallFlying` runs unchanged inside `GravityFrame` (the world is rotated so the galaxy's gravity is Minecraft's -Y). While the elytra are open the player always moves by Minecraft's physics and Mario is seated at the player's feet every frame (the existing `GXC_MSG_SEAT` path Minecraft movement uses). In the void (`!world.hasGravity()`) vanilla gravity is off and up stays frozen; a pure `CosmicWind` brings far-off players back. Mario's visible flight pose is the last task, after a spike.

**Tech Stack:** Java 25, Fabric (Minecraft 26.3), JOML, JUnit 5; Syati C++ module + dev Dolphin host for the Mario pose.

**Spec:** `docs/superpowers/specs/2026-10-05-galaxycraft-elytra-design.md`

## Global Constraints

- Galaxy units per block: `GravityFrame.SCALE` (80 units/block by default). Pure code in `fabric/src/main/java/dev/moui/galaxycraft/gravity/` takes blocks or galaxy units explicitly.
- Flight turn: a full 180° flip of up takes about 30 ticks (`FLIGHT_TURN_PER_TICK = Math.PI / 30`).
- Wind: free within 200 blocks past the farthest gravity reach; pull grows smoothly to 0.08 blocks/tick² over the next 100 blocks; 5 % drag per tick on the outward speed; never pushes outward.
- Gravity sources are **bodies**, not just spheres: the wind and the void test take `GravityBody` so flat space stations (planned next) plug in without changes.
- `/fly` keeps winning over the elytra (vanilla: creative flight beats gliding).
- Never edit sources while a `tools/gxvoxel.sh` run compiles or runs.
- User docs in Spanish (`docs/ELITROS.md`); code comments in English, the house style.

## Review Focus

1. Elytra break (or are unequipped) in the void → the player drifts with no gravity and the wind still brings them back; no crash, no stuck hold.
2. Entering a field upside down (gravity 180° from up) → `limitTurn` must not produce NaN and must finish in ~30 ticks (pinned in Task 2).
3. F6 changed mid-flight → flight keeps the player's own physics until landing; then the newly chosen mode takes over.
4. Landing in a Mario mode → Mario is released at the player's feet, on the ground, not inside it (WALK_LIFT path) and the player follows him again.
5. `/fly` toggled while gliding → creative flight wins, the elytra close, nothing is left holding `noGravity`.

```java
public interface GravityBody {
    Vector3d center();
    /** How far p is past this body's gravity (<= 0 inside it), p's units. */
    double outside(Vector3d p);

    record Sphere(Vector3d center, double reach) implements GravityBody {
        public double outside(Vector3d p) { return p.distance(center) - reach; }
    }
}

public final class CosmicWind {
    public static final double FREE = 200, RAMP = 100, PULL = 0.08, DRAG = 0.05;
    public static Vector3d push(Vector3d pos, Vector3d vel, List<? extends GravityBody> bodies) {
        GravityBody nearest = null; double best = Double.MAX_VALUE;
        for (GravityBody b : bodies) { double o = b.outside(pos); if (o < best) { best = o; nearest = b; } }
        Vector3d dv = new Vector3d();
        if (nearest == null || best <= FREE) return dv;
        Vector3d in = new Vector3d(nearest.center()).sub(pos).normalize();
        double t = Math.min(1, (best - FREE) / RAMP), s = t * t * (3 - 2 * t);
        dv.add(new Vector3d(in).mul(PULL * s));
        double out = -vel.dot(in);
        if (out > 0) dv.add(new Vector3d(in).mul(out * DRAG));
        return dv;
    }
}
```
- [ ] **Step 4:** tests PASS.
- [ ] **Step 5:** commit `feat: CosmicWind brings players far past every planet's gravity back`.
